Inverse Model Studio
From measurements back to the unknown parameters and fields: one problem, five methods, the same data, checked

Formulate the problem

Measurements, the physical model and geometry, and the unknowns: parameters, boundary conditions, or the zones of a field. Held-out measurements are never fitted and decide which method generalises best. The heat examples are the Inverse Heat Lab's.

Methods (same data)

What comes out

  • Estimated parameters from every method, with their 95 % intervals where the method gives one, side by side on the same data.
  • Reconstructed physical fields (temperature profile and map, the h(x) field) per method, against the known truth on the examples.
  • Validation: residuals, the error on held-out measurements, the identifiability diagnosis (what the data cannot determine), and whether each method recovered the known answer.
  • Cost: model runs and time per method: the adjoint gradient costs one extra solve whatever the number of unknowns.

The same in Python

      
import pinneapple_analysis.inverse_problems as inv

problem = inv.get_preset("rod_h_field").problem()          # or inv.InverseProblem(model, obs, params, validation)
print(inv.available_methods(problem))                       # which methods apply, and why not
out = inv.compare_methods(problem, ["least_squares", "adjoint", "autodiff", "bayesian"])
for row in out["table"]:
    print(row["method"], row["validation_rmse"], row["forward_evaluations"], row["truth_recovered"])
