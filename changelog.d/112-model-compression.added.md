- `pinneapple_analysis.surrogate.deploy` compresses a surrogate for deployment and **measures both sides of the trade in one object**: a `DeploymentReport` with the relative L2 the compression cost, the p50 latency it bought on the same rows, the bytes before and after, and whether the error stayed inside the tolerance the caller set. Measured on a trained 16→256→256→8 surrogate, one thread, 4000 rows: **ONNX Runtime dynamic int8 loses 0.40–0.54 % relative L2 and is 1.5x faster** (1.24–1.89x across runs) and 3.7x smaller on disk; torch's own dynamic int8 loses 0.5–1.4 % and runs 0.77–1.16x — it depends on the size and on this stack it does not pay; structured pruning gains 2.15x and costs **81 %** error at half the units, which the report records as *outside* tolerance: pruning without fine-tuning is not a deployment path here, and saying so is the point. int8 wins on batched inference and loses on a single row (0.90x at batch 1), so the batch is recorded with the number and the single-row timings go in `details`. TensorRT is declared, not executed — `tensorrt_status()` says why in the report (issue #112).
