- `pinneapple_analysis.trust.drift.DriftMonitor` is the monitoring half of the trust gate (#114): a window of served traffic is compared with a held-out validation baseline, **with labels** (error drift, RMSE ratio recorded) and **without them** (drift of the output distribution and of the model's predictive uncertainty). The `envelope` check reuses `TrustGate`, so a window outside the fitted distribution is an alarm with the same machinery the gate already uses. The limits are calibrated on a *second* held-out split — 0.99 quantile of the statistic over windows of the deployment size — so the false-alarm rate is a number that was chosen rather than a hand-picked cutoff, and measuring before calibrating raises instead of guessing. The `RetrainDecision` carries the verdict (`STABLE` / `REVIEW` / `RETRAIN`), whether to retrain and the sentence saying why; `write_record` appends it as one JSON line per window. A quantity the model cannot support (no labels, no uncertainty) is reported as *not run*, never as a pass.
