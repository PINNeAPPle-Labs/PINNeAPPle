- The plugin trust policy is stated once, in `pinneapple_plugins.policy`, printed by `pinneapple plugins policy` and quoted sentence for sentence by `docs/core_concepts/plugins.md`: what is checked at load time (declared dependencies, contract version, where the plugin came from, the registry entries it adds, its declared permissions) and what is deliberately not provided (process isolation, resource limits, syscall filtering, a sandbox — including in a subprocess —, enforcement of the declared permissions, revocation). (#1475)
- The plugin contract gains `registers` (kind -> names, contract 1.1): the loader now watches `pp.register` while `initialize()` runs and refuses a plugin whose declarations and registrations disagree in either direction, rolling back what it registered. This is the check for the honest plugin written against last year's API that loads, does half its steps and looks successful. A plugin written against contract 1.0 stays compatible, with what it registers recorded by `pinneapple plugins doctor` and marked as not verified. (#1475)
- `pinneapple_core.registry` reports every registration and removal to listeners (`add_listener`, `remove_listener`, `observe`), the hook the loader uses to attribute registrations to the plugin that made them; a listener that raises is dropped instead of breaking `pp.register`.
