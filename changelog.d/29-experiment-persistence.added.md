- `pp.Experiment` now saves and reloads itself: `Experiment.to_dict()`, `from_dict()`, `save(directory)` (writes `experiment.json`, next to the `result.json` a run already wrote) and `load(path)` rebuild the definition from the record. A problem that came from a preset is rebuilt through the preset, so its Python condition functions come back attached and the reloaded experiment runs — to the same predictions, not just the same config; a problem that did not is recorded with `resumable: false` and the condition functions it cannot restore, and fails with the existing clear error instead of a wrong answer. The record carries the problem fingerprint, so a record whose problem changed is refused. `pinneapple_app`'s experiment runner keeps its own trainer (model registry, per-epoch events, advisor retrains) but now describes what it ran with the library class: `ExperimentRunner.manifests()` returns one `pp.Experiment` record per model, with the seed and the fingerprint, and the benchmark payload carries them under `experiments` — so an app run and a script run are comparable and reloadable by the same class (issue #29).
