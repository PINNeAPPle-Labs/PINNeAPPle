- **One interface for the surrogates that learn on the geometry itself (#293):** `pinneapple_analysis.surrogate.geometry` gives every geometry-agnostic family the same three methods — `GeometrySurrogate.fit(samples)`, `.predict(points, normals, conditions)` returning the field *and* the integrals, and `.evaluate(held_out)` returning the relative L2, the integral error and the R² of the ranking. A sample is a point set of any size in any order (`GeometrySample`: points, normals, conditions, per-point fields, integrals, elements), so a variable point count, subsampling and batching are handled once, not per family. The integrals are computed by an `integrate` callable the case supplies and applied to the *predicted* field, so a predicted drag can never disagree with the pressure it came from. Implemented behind it: `transolver` (Wu et al., ICML 2024) and `pointnet` (Qi et al., CVPR 2017), wrapping the architectures the library already had. `FAMILIES`/`available_families()` list `gino` (Li et al., NeurIPS 2023) and the `MeshGraphNet` baseline as **not implemented here**, each with the paper, the dependency and what wrapping it would take — a caller never mistakes a stand-in for a model that is absent. Measured on a real solver (`benchmarks/geometry_surrogate_interface.py`, bodies labelled by the Hess-Smith panel method): the numbers are in `benchmarks/_out/geometry_surrogate_interface.json` and on `docs/guides/geometry_surrogate_families.md`.
