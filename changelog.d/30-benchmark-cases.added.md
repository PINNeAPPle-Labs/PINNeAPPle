- The official benchmark cases and the protocol that makes their table reproducible (issue #30, roadmap item B3): `pinneapple_tools.benchmark_suite.cases` declares three transient problems whose reference is a **closed form** -- `01 heat_1d`, `02 heat_2d` and `03 burgers_1d` -- and scores each of them inside the window it trained on (**in-domain**) and outside it (**extrapolation**), which is the number a leaderboard usually leaves out. `PROTOCOL` is data, not prose: the seeds (0, 1, 2), the training budget (300 epochs, 512 collocation points, 32x3 network), the metrics (`relative_l2`, `rmse`, `max_abs`), the interval (bootstrap over the evaluation points, 95%, 2000 resamples), the evaluation grids, and the tolerance a reproduction is allowed. `run_case` runs one case at that budget and returns the per-seed metrics, the interval and the cost; the page `docs/benchmark_cases.md` is generated from `benchmarks/cases/results.json`, so the published numbers cannot drift from the run. Measured on this machine: in-domain relative L2 **5.1e-3 / 2.2e-2 / 0.157**, extrapolation **0.58 / 0.81 / 0.79** -- the honest result is that a PINN trained on half the time window does not extrapolate, and the table says so instead of publishing only the first column. The command line is `python scripts/benchmark_cases.py --run | --docs | --reproduce | --check`; `--reproduce` trains again and reports every cell outside the tolerance (it reproduced every metric exactly on the machine that published them; the cost column is informational because it is a property of the machine), and `--check` is the CI gate for the declaration and the page.
