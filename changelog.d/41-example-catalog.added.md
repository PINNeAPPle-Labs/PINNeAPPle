- An example catalog with a CI tier (`examples/run_tiers.json`, `scripts/example_catalog.py`, `docs/guides/example_catalog.md`): every folder under `examples/` is now either run by CI or marked manual with a reason, and the reasons are measured rather than typed — `--measure` runs each example with a timeout and records what happened ("takes longer than 20 s", "fails when run: ModuleNotFoundError..."), and a missing third-party package or a name the repository does not have yet is derived from a checked fact (the same `check_example_imports` the import gate uses, so a fixed import cannot linger in one of them). `--check` is the gate and refuses an uncovered folder, a CI entry that points at nothing, a known-broken import inside the tier, and a tier whose declared caps exceed its budget; `--run` executes the tier, and the tests workflow runs both, so "runs in CI" means the example ran. Examples that pass cleanly are reported as promotable, which is how the tier is meant to grow (issue #41).
