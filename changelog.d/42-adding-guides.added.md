- "How to add" guides with the template file the issue asks for, and a test that keeps them honest: `docs/dev/adding_to_pinneapple.md` names the six extension points (a preset, a solver/method, a model architecture, a benchmark case, a data adapter, an app) with the starting file and the test that has to come with each one; `docs/dev/adding_a_preset.md` walks the preset path end to end — what a preset is, the four steps, the test, and the failure table that saves the questions people actually ask (an unnamed wall is a zero-Dirichlet wall, not an insulated one; `"analytic"` needs a registered closed-form matcher, `"reference"` runs the solver the preset declares). `templates/36_add_a_preset.py` is that guide as code: it registers a plate held at 0 °C and 100 °C, solves it through `pp.solve`, prints what it checked and asserts before it prints, so a contributor who runs it knows the path still works. `tests/test_adding_guides.py` fails if a page names a template, test or module that has moved, if the index loses one of the six extension points, if the guide loses its steps, or if the template stops running — which is what makes "an outside contributor adds a preset without asking anything" a property of the repository rather than an intention (issue #42).
