- `pp.viz.headless()` reports what a machine offers for off-screen rendering — pyvista and VTK, a display, `xvfb-run`, `libOSMesa`, `libEGL` — names the shortest recipe that fits it (`ready`, `install`, `xvfb`, `osmesa`, `egl` or `docker`) and prints that recipe's exact commands. `can_render` comes from a real render, attempted in a subprocess because VTK crashes the interpreter instead of raising when it cannot open a context, and a frame of one flat colour counts as a failure: that is what a half-configured Mesa looks like. `python -m pinneapple_tools.visualization.headless` prints the report and exits 1 when the frame did not come back, so a CI job can gate on it. macOS and Windows are reported as `ready` without a `DISPLAY`, because they do not need one (issue #66).
- `docker/headless/Dockerfile` is that recipe with nothing left to decide: xvfb, Mesa's software GL, ffmpeg for `pp.viz.turntable`'s MP4 and the package with its rendering extras, with `xvfb-run -a` as the entry point and the self-check above as the default command. `docs/guides/headless_rendering.md` documents the three recipes and the image, and quotes every command from the module, so the page and the code cannot drift (issue #66).
