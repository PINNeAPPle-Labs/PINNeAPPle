- **Changed:** the bundled CalculiX image is multi-platform and pinned (issue #70). The base is `debian:bookworm-slim` by the digest of its manifest list -- one value for every architecture, so `linux/amd64` and `linux/arm64` build from the same `Dockerfile` -- and the `calculix-ccx` package is installed at its Debian version (`2.20-1`) and asserted at build time, both with `dpkg -s` and against the binary's own `ccx -v`: a mirror that serves another build fails the image build instead of a result later. `runner.build_for(platform)` builds either architecture under its own tag (`pinneapple/calculix:local-amd64`, `:local-arm64`, so the two do not overwrite each other in one store) and `runner.image_smoke(platform)` is the gate: it builds the image for that platform and runs a real CalculiX case inside it -- a C3D20R cantilever under a 1 kN tip load, whose deflection Timoshenko's theory fixes to 1 % -- and compares. Measured here: ccx 2.20 in the `linux/arm64` image, tip deflection -1.5128 mm against 1.5268 mm (-0.92 %), 37 s to build and 1.4 s to run once built. `.github/workflows/calculix-image.yml` runs the same function for both platforms on a runner; while the repository's runners are unavailable the identical gate runs locally through `scripts/calculix_docker_smoke.py` (and `tests/test_calculix_image.py`, which skips without Docker).
