- `Trainer` can now be interrupted and resumed, and the resumed run follows **the same loss curve** (issue #76, item G3). `TrainConfig(save_last=path)` writes a resumable checkpoint at the end of every epoch and `TrainConfig(resume_from=path)` continues from it — with `epochs` meaning the *total* the run should reach, and the history coming back with the epochs already done. The checkpoint carries what continuing actually needs: the model weights, the optimizer state, **the RNG state of torch, numpy and `random`** (without it the dropout in the second half draws different numbers), the AMP scaler, the **scheduler** state and the loss-balancer state. `Trainer` also takes `scheduler=` now — an instance, or a factory `optimizer -> scheduler` for the optimizer it builds itself — and steps it once per epoch. `pinneapple_neural.trainer.checkpoint` gains `rng_state()` / `restore_rng()` (plain tensors and numbers, so the file loads under `torch.load(weights_only=True)`). Tested by equality: four epochs straight and 2 + 2 with a checkpoint in the middle produce the same curve and the same weights (`tests/pinneapple_train/test_trainer_resume.py`).
