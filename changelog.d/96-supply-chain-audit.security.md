- `scripts/licensing/supply_chain.py` is the dependency and licence audit the build runs (`make audit`, also inside `make gates` and in the security workflow): every declared dependency — the core and all sixty-odd optional extras — has a **tested minimum** recorded in `docs/dev/dependency_floors.json`, generated into `constraints/floors.txt` and installed by `.github/workflows/floors.yml` on the lowest supported Python, and the **licence each one declares** recorded in `docs/dev/dependency_licenses.json` and published as a table in `docs/licensing.md`. Loosening a bound without re-recording fails, because the install could then reach below what was run; a copyleft dependency fails until it is a decision under "Dependencies accepted with a copyleft licence", where `gmsh` (GPL-2.0+, an opt-in extra) now is; an unreadable licence fails instead of being assumed permissive. The audit is offline and reads only the tree, so the same checkout gives the same answer here and in CI (issue #96).
- `xarray` and `zarr`, the two core dependencies that were declared without a lower bound, now declare one (`xarray>=2024.1`, `zarr>=2.16`): a dependency with no floor is a dependency tested at whatever pip resolves (issue #96).
