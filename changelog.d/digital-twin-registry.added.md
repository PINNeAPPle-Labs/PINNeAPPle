`pinneapple_systems.digital_twin.library` gains a named-scenario registry and a status manifest. A `Scenario` is a slug, a name, parameter overrides and a provenance line; it runs through the same `simulate` as anything else, saves to JSON, and can be handed to somebody else. `manifest()` is the library's status page as data — every twin, its fidelity, every scenario, the verdict of each run, the worst balance against its own tolerance and anything extrapolated — and `python -m pinneapple_systems.digital_twin.library.scenarios --check` turns it into an exit code for CI. Four of the eleven shipped scenarios are declared `expect="finding"`: an infeasible operating point is a result, not a failure, and the check is strict in both directions, so a finding that stops being reported is a regression too. The registry itself moved to `library/registry.py`, so scenarios can enumerate twins without importing the package that imports them (#1802, registry and scenarios only).
