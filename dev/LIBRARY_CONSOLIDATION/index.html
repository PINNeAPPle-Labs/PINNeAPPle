    Library consolidation: reusable logic outside the library¶

    Rule: reusable logic goes in the library; apps, examples, scripts, notebooks and the satellite repos only compose library calls. A user gets every feature with pip install pinneapple, through a pp. shortcut or a public module. App-specific glue (FastAPI routes, request schemas, HTML/JS, deploy files, auth) stays in the app.

    This page is the inventory behind that rule (audit of 2026-10-13, main at 8e8ff8c). For every piece of reusable logic found outside the pinneapple* packages it records where it is, what it does, whether the library already has it, and the verdict:

    • move: no library equivalent; it goes into the library with a public API, docstrings and tests, and the caller imports it from there (a thin shim stays where outside users may import the old path);
    • switch: the library already has it; the caller is switched to the library;
    • glue: app- or example-specific (routes, UI, deploy, narrative demo code); stays;
    • stays: kept on purpose for the reason given (frozen record, release tooling, external reference replica, ...).

    The pull requests that implemented it and what is still to do are at the end. scripts/check_app_helpers.py (run in CI) keeps new duplicates out; see AGENTS.md and CONTRIBUTING.md.

    Work streams that were in flight during the audit are left alone and audited after they merge: observatory AI features, playground, zoo v2, black-hole zoo (examples/black_hole_weather, pinneapple_physics/blackhole), multiscale ensemble (pinneapple_physics/ensemble.py), rover dashboard v3 (dashboard/static.py, studio, terramechanics), equal-budget benchmark / benchmark API (pinneapple_analysis/benchmark, aero/panel.py, inverse_problems/heat_transfer.py, Benchmark exp/09).
