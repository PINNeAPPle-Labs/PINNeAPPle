    The physics-AI workflow, stage by stage: open tools and public datasets¶

    This page is the companion of PHYSICS_AI_INTEROP.md. That one is organised by integration (INT-001 … INT-015) and answers "what does this repository do today?". This one is organised by stage of the workflow and answers the question a person building a pipeline asks first: at this step, which open tools exist, which public datasets feed it, and how far does this repository already get?

    The map is not a document first. It is pinneapple_catalog.stages, and this page is generated from it, so a row here and a row in the code cannot disagree. Every claim below is checkable:

    pytest tests/pinneapple_catalog -q
python -c "from pinneapple_catalog import stages; print(stages.coverage()['totals'])"
python -c "from pinneapple_catalog import stages; print(stages.to_json('inverse')['counts'])"

    The thirteen stages are the Flow palette's¶

    STAGE_IDS is the palette's SECTION_IDS, and a test compares the two lists. That is deliberate: the palette is what a user sees in Flow Studio, so a stage that exists in the map and not on the canvas would be a catalogue of something nobody can build. The last section, library, is the palette's drawer of generated auto.* calls — it is carried so the lists match exactly, it is marked kind="internal", and it asks no question and holds no tools.

    How a tool is described, and what the description refuses to claim¶

    Field What it says How it was obtained
    license an SPDX id, or the licence's own name where no id exists read from the artefact that governs the code: the repository's LICENSE through the GitHub licence API, or the distribution metadata on PyPI for a package that ships none
    license_verified whether that read happened here True for the reads above; the ten rows that were False until 2026-11-25 are listed at the end of this page with what their text says
    integration wired / named / candidate wired means a module in this repository calls it, and a test resolves that module's path; named means the repository mentions it (a recommender, a lazy export, a docstring) with no path that would run it; candidate means nothing here touches it
    also_in the TOOL_CATALOG id, where the same tool has a page there so the two catalogues reference each other instead of disagreeing

    Two things the licence column is not. A verified licence is not a commercial clearance: GPL-3.0, AGPL-3.0 and ODbL are read correctly and are still unusable in a closed product, which is why the id is carried rather than a boolean. And an unread licence is not a licence that forbids use — it is one this checkout did not open, and the row says so rather than guessing.

    The datasets side is a filter, not a copy: CatalogEntry in pinneapple_data.datasets.catalog gained the stages it feeds, so catalog.entries(stage="inverse") and stages.datasets("inverse") are the same list by construction. A test asserts it, and stages.unassigned_datasets() names any catalogued dataset that no stage claims.

    What the shape says¶

    Four things are worth saying plainly, because they are the reason to build the map at all:

    • The workflow is a T at the solvers. 27 tools at the classical-solver stage, 13 of them wired, against 11 and 1 at the inverse stage and 10 with 2 at the ROM stage. The repository is strong where the physics is known and thin where it has to be inferred from data — which is exactly the stage the trust layer and the design loop depend on.
    • The inverse stage has one wired tool, and it is not a sampler. PySINDy recovers an equation from data; it does not produce a posterior. PyMC, emcee, dynesty and UltraNest are catalogued and unused, so the "uncertainty" this library reports is still a seed-ensemble disagreement (bundle_uq.seed_ensemble says so itself). Closing that gap is the shortest path from "a number" to "an uncertainty".
    • Four stages have no datasets at all — equations, optimization, viz, export. For viz and export that is honest (they consume a result rather than a public archive); for optimization it is a real hole: comparing a design loop needs the reference optimum of a case, and no catalogued dataset carries one.
    • The copyleft list is short and specific: OpenFOAM (GPL-3.0), FEniCSx and UFL (LGPL-3.0), Firedrake (LGPL-3.0-or-later), preCICE (LGPL-3.0), CasADi, RBniCS, dolfin-adjoint and OpenTURNS (LGPL-3.0), OpenRadioss (AGPL-3.0-or-later), jax-fem and REBOUND (GPL-3.0-or-later), DEAP (LGPL-3.0), UltraNest (GPL-3.0), and — new to this page — AirfRANS under ODbL-1.0, the one dataset whose licence is share-alike. Outside the copyleft list and harder to live with, FluidX3D forbids commercial use outright.

    The map in the planner: a proposal now says which stages it spans¶

    A table nobody queries is a document. The map is joined to the flow planner in pinneapple_flow/stage_fit.py: FlowBuilder.proposal() annotates every proposal with stage_map, and the annotation travels inside the flow (flow.meta.stage_map), so the Studio, the API and a saved flow all see the same thing.

    from pinneapple_flow.stage_fit import fit
fit([{"id": "calibrate", "type": "inverse.calibrate"}])
# {'stages': [{'id': 'inverse', 'wired': 1, 'wired_tools': ['pysindy'], 'datasets': [...],
#              'readable_datasets': [...], 'gap': 'The library calibrates with its own optimisers; ...'}],
#  'thin': [{'id': 'inverse', 'wired': 1, 'gap': '...'}], 'available': True, ...}

    thin is deliberately not "zero wired tools". It is "at most one", because a stage where a single external tool is wired offers no choice at all: the planned flow runs that step on PINNeAPPle's own code whatever the user wanted. The stage's gap sentence goes with it, so the finding is actionable rather than a score.

    A thin stage is also recorded as a decision (stage.coverage) with the rule's own citation status, so the reason travels with the flow instead of living in a returned dict that a saved flow would lose. The rules gate (tests/test_flow_decisions.py) requires every rule to cite a reference or to say why it has none; this one says it is a property of this repository's map, not a literature rule.

    What it looks like on a real plan — plan_heuristic("identify the conductivity of a rod from measurements") spans six stages and flags one:

    Stage Wired tools there Verdict
    problem 2 fine
    equations 5 fine
    solvers 13 fine
    data 8 fine
    inverse 1 (PySINDy) thin — recorded as a decision
    export 6 fine

    The join degrades instead of failing: without pinneapple_catalog installed, fit() still reports the stages the flow spans and says in reason why no coverage came back. An empty map would read as "nothing is available anywhere", which is a different and wrong statement.

    The ten licences this page had not read, and what they say¶

    These ten rows carried a licence nobody here had opened. They were read on 2026-11-25, each one at the place named in its license_source, and license_verified is now True on all of them, so stages.coverage()['totals']['license_unverified'] is 0.

    Tool The licence, as its own text says it What it implies for a paid study and for distribution
    Gmsh GPL-2.0-or-later, plus the Gmsh exception commercial use fine; the GPL reaches a modified Gmsh, and the exception keeps it away from the caller that links it
    SALOME LGPL-2.1 commercial use fine; a modified SALOME stays LGPL, and linking does not reach the caller
    FluidX3D custom: research, education and personal use, "Commercial use is not allowed" not usable in delivery: nothing may be sold, nor a paid service whose value derives from it; no military use, no AI training on the source

    Two of the reads changed the row rather than confirming it. REBOUND's own header says "version 3 or any later version", so GPL-3.0 became GPL-3.0-or-later. Matplotlib's text is an agreement between the Matplotlib Development Team and a licensee, not a BSD-family licence, and the row that called it "BSD-style" now quotes the obligation it actually carries.

    FluidX3D is the one entry whose licence forbids what this repository sells, so is_open is False for it: a custom licence that bans commercial use is source-available, not open-source.

[(t.id, t.license) for t in stages.tools() if not t.license_verified]   # []
[t.id for t in stages.tools() if not t.is_open]                         # ['fluidx3d']

    Decisions left open, each one a row and not an omission¶

    1. Agents are not a stage. The palette has no section for the engineering agent, so the map has none either — the intent compiler and the advisor live under problem and optimization for now. If the workflow gains an agent step, it belongs in SECTIONS first and in this map second, which is the order the test enforces.
    2. named is not wired, and ten tools sit there. They are named by a recommender or an optional-dependency table, with no path that runs them. Promoting one means writing the adapter, not editing this map.
    3. The map does not rank. It says which tools serve a stage and how far this repository goes with each; it does not say which of two candidates is better for a given problem. That ranking exists for solvers in tool_recommendation.recommend_tools, and it is deliberately problem-scoped, not stage-scoped.
    4. Dataset stage tags are a judgement, not a measurement. A dataset is tagged with the stages it feeds (pdebench feeds physics-AI training, data, surrogates and validation). Two people could tag the same archive differently; the tag lives in one place so the disagreement is a one-line edit rather than thirteen.
