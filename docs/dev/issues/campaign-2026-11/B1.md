## Summary

MORPH is a simulated machine that starts without knowledge of its own structure: a beam or wing section whose mass, stiffness and damping are withheld from the software operating it. It perturbs the structure, identifies those parameters, selects a predictive model family from evidence, and optimises a morphing configuration for a lift or stiffness target. The reference solver run that plays the role of measurement is sealed until the prediction is hashed, giving a verifiable ordering between the two.

## Question

On a held-out configuration never used for identification or optimisation, does the loop recover the true parameters and predict the reference lift within tolerance when the prediction is committed before the reference solve runs?

## Why run it

It turns a slogan into a sequence with a timestamp on the prediction, and exercises the identifiability machinery where the answer is known, so failures are caught before they are read as physics.

## Physical model

Beam with von Kármán axial stiffening:

EI w'''' + c w_dot + rho A w_ddot - (EA/2L) w'' \int w'^2 dx = f(x,t)

with unknown theta = {EI, rho A, c, EA}. Aerodynamics is quasi-steady strip theory with a lift-curve slope and stall cut-off, or a vortex-lattice solve in 3-D.

Regime groups: mass ratio mu = rho_fluid b / (rho_solid t); reduced frequency k = omega b / U; Reynolds Re = U c / nu; damping ratio zeta; parameter sensitivity S_p = (dY/dp)(p/Y). Left out: separated flow, compressibility, plasticity, real actuators, nonlinearity beyond moderate rotation. A result here describes a shape family, not a mechanism.

## Geometry and inputs

A parametric beam extruded from SDF cross-sections with camber distribution as the morphing variable, plus a 3-D airframe whose morphing variables are sweep, span and camber inside a fixed planform envelope. Truth parameters come from one declared prior and seed; the perturbation set is a D-optimal design.

## Solver and engine

Structure: `pinneapple_simulation.numerical_solvers.nonlinear_beam_fem` (`NonlinearBeamNewmarkFEM`, `solve_nonlinear_beam_transient`), cross-checked with `solid_fem`. Aerodynamics: `pinneapple_design.aero.vlm` (`build_lattice`, `solve`) at low incidence, with `pinneapple_design.aero.case3d` (`write_case3d`, `run_case3d`) as the reference solver. Selection uses `pp.compare`; the inverse side uses `inverse_problems.compare_methods`.

## What is missing (the work)

1. An orchestration module (proposed `pinneapple_analysis/selflearning/loop.py`) running perturb → identify → select → optimise → seal → verify as one recorded experiment.
2. A seal-before-solve guard: the seal is post-hoc today, so nothing stops the reference solver from running before a prediction exists.
3. An aeroelastic coupling layer between the beam transient and the VLM solve.
4. A committed three-way split (identification / optimisation / verification) with a leakage check.
5. An actuator mass and power penalty on the morphing variables.

## Experiment protocol

Case matrix: 2 geometries x 3 noise levels (0, 2, 5 %) x 2 excitation designs x 2 selection policies = 24 cases, seeds 0/1/2. Mesh independence at 64/128/256 elements, Courant below 0.5, reported with `verification.convergence.mesh_independence_study`. Optimisation stops at a relative objective change below 1e-4 over ten iterations. Budget: order 10^2 CPU-hours for the beam, 10^3 with `run_case3d`.

## Baselines, references and verification

Checked against the closed-form first cantilever root (beta_1 L = 1.875104) and the linear limit of the von Kármán term; aero against vortex-lattice and panel solutions at equal alpha. Baselines: a fixed nominal parameter set, a family chosen without evidence, the unoptimised shape, and an optimiser run on unidentified parameters.

## Metrics

- epsilon_theta = |theta_hat - theta_true| / theta_true (percent), per parameter.
- Interval coverage: fraction of 95 % intervals containing the truth.
- Selection regret: selected-family objective minus the best, normalised.
- epsilon_CL: sealed-prediction error against the reference solve (percent).
- Delta C_L: lift gain over baseline (percent).

## Deliverables

A manifest per case with the sealed prediction, its hash, both timestamps, the recovery table with intervals and the evidence comparison. Across cases: epsilon_theta against noise, predicted against reference C_L with the identity line, and a render of the shape morphing through configuration space.

## Acceptance criteria

- No fit without its identifiability report.
- At 2 % noise, epsilon_CL < 8 % and epsilon_theta < 5 % for EI, < 3 % for rho A.
- The seal timestamp precedes the reference-solve timestamp in every manifest.
- Re-running a case from its manifest reproduces every metric exactly at the same seed.

## Realizability and evidence class

Fills `mathematical_consistency`, `numerical_stability`, `physical_plausibility`; leaves `experimental_validation` and `technological_feasibility` not assessed. `PLAUSIBILITY_CLASS`: `extrapolated`; `established` needs a physical beam with measured EI.

## Risks and failure modes

1. Inverse crime: generator and fitter share a model. Mitigation: different discretisation on each side.
2. EI and rho A trade off statically. Mitigation: D-optimal excitation; report non-identifiable directions.
3. Panel methods cannot separate. Mitigation: constrain alpha; report where separation begins.
4. Held-out reuse. Mitigation: one verification pass, split committed in advance.
5. Free morphing. Mitigation: mass and power penalty as a Pareto axis.

## Out of scope

- Physical morphing hardware, actuators, wind-tunnel tests.
- Turbulent, compressible or dynamic-stall aerodynamics.
- Optimisation beyond lift/stiffness against mass; flight dynamics.
