# Model and dataset inventory for the zoo (2026-10-13)

This is the inventory of every pre-trained model and dataset found across the organisation that could ship in
`pp.zoo` / `pp.datasets`, with a verdict for each one. **Quality is the gate; quantity is not a goal.** Anything
derived from client work is excluded entirely and is not described here.

Sources surveyed:

- this repository (`apps/`, `examples/`, `lab/`, `data/`, `runs/`, `pinneapple_*`);
- `PINNeAPPle-Labs/PINNeAPPle-Benchmark`: experiments 02–08 on `main`, and experiment 09 on branch
  `exp/09-equal-budget`.

## The gate

**Model.** A model ships only if all of the following hold:

- Its held-out error against an independent reference is documented and reproducible. The reference may be analytic,
  a classical solver whose own verification is documented, or published data.
- It passes the physics checks of its trust report: the decision must be `APPROVED`.
- It has no known failure on its stated range.
- Its validity range is recorded.

The gate is enforced in code. `scripts/zoo/build_assets.py` computes each card's metrics with the zoo's own
`evaluate()` and runs `pp.zoo.validate()`. A model that is not `APPROVED`, or that breaks its acceptance limits, is
not written.

**Dataset.** A dataset ships only if both hold:

- It was generated by a verified solver with mesh or convergence evidence, or it comes from a public source with a
  compatible licence.
- Its schema, splits and provenance are documented.

### Trust-report physics checks

All four models pass every check (decision `APPROVED`, score 1.0).

- **`airfoil_cst_rans_mlp`**
  - Lift-curve slope within 15 % of thin-airfoil 2π/rad on the held-out shapes; the worst deviation is 4.9 %.
  - Cl increases with α below stall (α −2…10°).
  - NACA 0012 symmetry: |Cl(0)| and |Cl(2°)+Cl(−2°)| ≤ 0.01 (measured 0.0009).
  - Cd > 0 and finite on 2000 random in-range inputs.
- **`heatsink_forced_mlp`**
  - More airflow, a more conductive material or a wider source never raises the resistance. The share of held-out
    designs violating each is 0 %, 0.35 % and 0.23 % (limit 1 %).
  - Pressure drop rises with velocity (0 % violating).
  - R > 0 and ΔP > 0.
- **`heatsink_natural_mlp`**
  - A more conductive material, a wider source or more power never raises the resistance. The share of held-out
    designs violating each is 0 %, 0 % and 0 % (limit 1 %).
  - The power law is checked but not enforced in training, because the engine's own resistance rises with power on
    0.5 % of designs (up to +0.7 % for a +5 % step).
  - R > 0.
- **`rover_contact_grc1_viper`**
  - On a 66×59 grid over the whole box there are no violations of:
    - dFz/dz ≥ 0;
    - dFx/ds ≥ 0 for slip ≤ 0.3;
    - the Mohr–Coulomb traction limit;
    - My ≥ R·Fx.

### Where the references come from (independence)

- **Airfoil.**
  - The training data, the held-out shapes and the NACA runs all come from the same solver and grid. The held-out
    error is therefore interpolation error.
  - The solver itself is verified:
    - a 3-grid study on NACA 2412 at α 4°: Cd GCI 1.9 % with observed order 2.4, and Cl within 0.02 %;
    - XFOIL: Cl −2.3 %, Cd +4.5 %;
    - lift slope 0.110/° against 0.110/° from thin-airfoil theory;
    - NASA TMR SST, NACA 0012: Cd 0.00812 vs 0.0081.
  - The zoo also stores the XFOIL polar as an independent-solver split.
  - Known bias: drag at high lift reads about 14 % high on the 20k-cell campaign grid. The card states this.
- **Heat sink.**
  - The reference is the physics engine the model was trained on.
  - The engine is validated against independent methods:
    - Lee et al. spreading resistance (1–5 %);
    - Stephan developing-flow Nu with ε-NTU (0–5 %);
    - fully developed friction (2–4 %);
    - Elenbaas (2 %);
    - FVM grid convergence (< 2 %).
- **Rover.**
  - The reference is the analytic Wong–Reece model, evaluated by quadrature (GL96 vs `quad` within 3e-8). The
    held-out set is a disjoint Latin hypercube.
  - Against published single-wheel tests, the Wong–Reece model's drawbar-pull RMSE is 4–14 N (dataset
    `single_wheel_tests`). That is larger than the surrogate's own error, and the card says so.

## How to add a model or dataset

1. Make it pass the gate above, with the evidence in the repository.
2. Add it to `pinneapple_hub/zoo/_catalog.py` (card or dataset description, acceptance limits, guard metrics) and,
   for a model, an adapter in `_models.py` (predict, metrics, physics checks, fine-tuning hooks).
3. Run `python scripts/zoo/build_assets.py --rover DIR`. This regenerates the assets, cards (with metrics and trust
   report) and the manifest; the build is deterministic. To add one item without touching the published ones, use
   `--only NAME` (with the training directory of a model trained by its own script, e.g. `--heatsink-natural DIR`)
   or `--hub-only STAGING_DIR` (Hub-only datasets).
4. Run `pytest tests/test_model_zoo.py`.
5. After the merge, the publish workflow uploads to the Hub.
