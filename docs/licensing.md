# Licensing

What this repository promises about the code inside it, about code adapted from elsewhere, and about what it
depends on. The rule that can be checked by a machine is a script; the rest is a decision written down so a
contributor does not have to guess (issue #48).

## The repository

PINNeAPPle is distributed under the **Apache License 2.0** ([`LICENSE`](../LICENSE)). It is permissive, it grants a
patent licence, and it asks for the notices to be kept — which matters for a library that ships third-party material
next to its own.

## Contributions: inbound = outbound, no CLA

A contribution is accepted under Apache-2.0, the same terms the project ships under. There is **no Contributor
License Agreement** and **no required DCO sign-off**.

- **No CLA.** A CLA exists to let a project relicense contributions it received. This project has no such intention:
  it is Apache-2.0 today and the copyright stays with the contributors. Asking every contributor to sign away
  rights the project does not need is friction with no benefit.
- **No mandatory sign-off.** Apache-2.0 does not require a `Signed-off-by` line, and the repository's history does
  not carry one. Adding the requirement retroactively would fail every existing contribution. A sign-off is
  welcome and never required.

What a contribution does need is what the pull request template already asks: the change, its tests, a changelog
fragment when it is user-visible, and a licence that is compatible with the project's.

## Code adapted from elsewhere

- **GPL and AGPL code is never copied into this repository**, in whole or in part, not even into a module that is
  "not really used". The *idea* is not copyrightable and may be implemented from scratch; the *expression* is.
  This is the rule the pull request checklist states in one line.
- Every adapted file gets an entry in [`NOTICE`](../NOTICE) naming the source project, its copyright line and its
  licence. The entries are factual: file, source, licence. `docs/dev/rea_harvest/ledger.json` keeps the full
  provenance for the material harvested in 2026.
- Permissive licences (MIT, BSD-2/3, Apache-2.0, ISC, Zlib, MPL-2.0) are what this repository has accepted so far.
  A weak-copyleft licence (MPL-2.0) is acceptable for a dependency; a strong one (GPL, AGPL) is a decision that
  goes in this file first, never a silent addition.

## No per-file licence headers

There is one `LICENSE` at the root and one `NOTICE` for third-party material; individual files carry no banner.
A header repeated in two thousand modules drifts — one file ends up with a year that is wrong, another with a
holder that never existed — and it duplicates what the repository already states unambiguously. Where provenance
matters, it is in `NOTICE`, next to the file it names.

## Dependencies

The core's dependencies are declared in [`pyproject.toml`](../pyproject.toml). The policy is: **permissive by
default, copyleft as a decision**. `scripts/licensing/dependency_licenses.py` reports what a declared dependency
says about its own licence in the current environment; `scripts/licensing/supply_chain.py` is the audit, because
"what this interpreter happens to have installed" is not the same question as "what this repository promises":

- **Every declared dependency has a tested minimum**, core and every optional extra, recorded in
  [`docs/dev/dependency_floors.json`](dev/dependency_floors.json). The floor is the lower bound in
  `pyproject.toml`; `.github/workflows/floors.yml` installs `constraints/floors.txt` — every core floor pinned with
  `==`, generated by the same script — on the lowest supported Python and runs the fast suite. Loosening a bound
  without updating the record fails the gate, because the install would then reach below what was tested, and
  raising one without re-recording fails too, because the new floor has not been run.
- **Every declared dependency's licence is listed**, in [`docs/dev/dependency_licenses.json`](dev/dependency_licenses.json)
  and in the table below, which the script generates. The licence is read from installed metadata (PEP 639
  `License-Expression`, else the trove classifier): observed, never guessed. A dependency the recording environment
  did not have is named in `unobserved` rather than filled in, and a core dependency may not be unobserved at all.
- **A copyleft dependency fails the gate** unless it is a decision under [Dependencies accepted with a copyleft
  licence](#dependencies-accepted-with-a-copyleft-licence).
- **A release that spells its licence differently is not a failure.** The record names the version each licence was
  read from, so an interpreter holding a different wheel is compared against the release the record names rather
  than against its string: pandas declares `BSD License` in 3.0.5 and `BSD-3-Clause` (PEP 639) in 3.1.1, plotly
  `MIT` in 7.1.0 and `MIT License` in 5.24.1 — the same licence each time. What is not release-dependent is the two
  failures that matter, a copyleft licence and a licence nobody can read, and those fire on whatever release is
  installed.

```console
$ python scripts/licensing/supply_chain.py --check     # the gate, offline, same tree -> same answer
$ python scripts/licensing/supply_chain.py --record    # after changing a dependency, with the reason in the commit
$ python scripts/licensing/dependency_licenses.py --fail-on-copyleft   # the core alone, this environment
```

`unobserved` in the record is a list of names, not a shrug: it says which dependency no recording environment has
ever had installed, so a reader knows exactly how much of the table was actually verified. A dependency that *is*
installed while its metadata names no licence at all is listed apart, in `unreadable`, with what the metadata said:
that is a different fact from "not installed here", and the record keeps the two apart rather than reporting the
second when it means the first. It is never assumed permissive — a core dependency in `unreadable` fails the gate so
that the licence gets named by hand, and an extra stays named in the table instead of being filled in.

### Why the five that are not in the table are not in it

The record was refreshed on a dedicated environment (Python 3.11, the project installed with every extra, one extra
at a time, so a failure names one extra and not the whole list). Three are not on PyPI in a form that installs here,
and two install but say nothing about their licence in their own metadata:

| Dependency | Why it is not in the table |
|---|---|
| `emmiai-noether` | every version published requires Python `>=3.12`; the recording environment is 3.11 |
| `fenics-dolfinx` | publishes no distribution on PyPI at all (conda and the FEniCS PPA only), so `pip` finds no version to install |
| `petsc4py` | publishes an sdist and no wheels; building it needs a PETSc installation to build against, and the recording environment has none (no `PETSC_DIR`, no `petsc-config`) |
| `fmpy` | installs (0.3.32), but its metadata carries no `License-Expression`, no `License ::` classifier and an empty `License` field. The wheel ships a licence file that opens with "FMPy is released under the 2-Clause BSD license" — read by a person, not by the gate |
| `genesis-world` | installs (1.4.5), same empty metadata. The wheel ships the Apache License 2.0 text in `licenses/` |

`pip` resolves an extra as one unit, so the failed `fenics` extra took `mpi4py` down with it; installing `mpi4py` on
its own worked, and it is in the table. `noether` and `fenics` are the only two extras that cannot be installed on
this interpreter at all — the record says so rather than dropping them from the declaration.

## Dependencies accepted with a copyleft licence

A copyleft dependency is a decision, and it is written here before the gate stops failing on it. Each entry says
what the dependency is, why it is acceptable next to an Apache-2.0 package, and what a user inherits.

- `gmsh` — the Gmsh mesher's Python bindings (GPL-2.0-or-later), in the `cfd`, `geometry`, `fitmesh`, `geom` and
  `all` extras. It is a separate program invoked through its Python module (`gmsh.initialize()` starts a mesher
  process; nothing of it is linked into, imported by or redistributed with this package's modules), so it does not
  make the core anything other than Apache-2.0. It is opt-in: a user who does not mesh with Gmsh never installs it.
  A user who does installs a GPL-2.0+ component and inherits those terms for it. The same applies to `cadquery`
  (Apache-2.0/LGPL for its OpenCascade dependency), which lives in the same extras.
- `asyncua` — the OPC UA client and server (LGPL-3.0-or-later), in the `twin` and `digital_twin` extras. It is the
  one dependency here that *is* a library rather than a program: `OpcUaTwinServer` publishes a twin on an endpoint and
  `OPCUAStream` polls one, so a user who exports a twin to OPC UA installs it and links it. LGPL is weaker than the
  GPL on purpose: a program may use an LGPL library without becoming LGPL itself, provided the library is not
  modified and the user can replace it. This repository does neither modify nor vendor it: it is imported from
  `site-packages` inside the function that uses it — never at module import, so nothing needs it to import the
  package — it is not redistributed in a wheel, and none of it is copied into this code. Uninstalling it and pointing
  the endpoint at another OPC UA stack is a change in one place (`OpcUaTwinServer` or `OPCUAStream`), which is what
  the LGPL asks for. A user who does install it inherits LGPL-3.0+ for that component, and for nothing else. The
  alternative was to vendor an OPC UA implementation, which would have put LGPL-derived code inside an Apache-2.0
  package — worse for everyone.

## Using this repository's code elsewhere

Apache-2.0 allows it, including commercially. Keep the `LICENSE` and `NOTICE` files with any substantial portion
you redistribute, and state what you changed. Nothing else is asked.
