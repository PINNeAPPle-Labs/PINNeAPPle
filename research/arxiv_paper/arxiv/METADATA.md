## Abstract (plain text, for the arXiv field)

```
Libraries for physics-informed learning are routinely compared by their published accuracy, on different problems, grids and budgets, so the comparison does not isolate the library. We report a preregistered evaluation whose protocol was committed before any result was produced, and whose every quantitative statement is regenerated by a script from an immutable run record. Three neural-network libraries for partial differential equations (PINNeAPPle, DeepXDE and PhysicsNeMo-Sym), one operator-learning baseline (neuraloperator) and the operator and inverse solvers of PhysicsNeMo are exercised on four forward benchmarks (Burgers, Poisson, Helmholtz, Allen-Cahn), one operator benchmark (FNO on Darcy 64x64) and one inverse problem (identifying the viscosity of Burgers), on one CPU, one thread per run, with every run's configuration, versions and load average recorded.

Three results stand out. (i) Under an identical configuration---the same network, the same weights, the same points, the same number of iterations---the three PINN libraries return the same answer to the precision the comparison can resolve: the paired per-seed ratio of their errors after 2000 iterations is 1.00 [0.96,1.00] on Poisson and 1.00 [1.00,1.00] on Helmholtz, with Burgers the one problem where float32 round-off separates them (0.94 [0.47,1.04] for DeepXDE against PINNeAPPle). The cost per iteration is within +5% and -10% of DeepXDE's and 1.4-1.9x lower than PhysicsNeMo-Sym's. (ii) Under each library's own recipe and a 240 s CPU cap, the defaults decide the outcome: across the three recipes the relative L2 error spans 166x on Poisson and 1156x on Helmholtz, and no recipe reaches a useful accuracy on Allen-Cahn. (iii) A protocol is not bookkeeping: applying it to the inverse problem exposed an adaptive loss-weighting rule in PINNeAPPle that left the identified viscosity 12.5x too large; the cause was isolated by single-knob diagnostics, and the fixed default reduces the error to 3.4x, still behind DeepXDE's 2.2x.

We then ask the question the same libraries raise but do not answer: once a prediction exists, can its physics be checked without a reference solution? On a controlled corpus of 72 predictions over six problems, checks that need no reference (boundary and initial data, declared bounds, non-finiteness, PDE residual) flag 28 of 36 single-defect predictions, while the residual check is scale-invariant for a homogeneous equation and its accuracy is limited by the finite-difference floor of the grid---0.73 of the term scale for Burgers at the benchmark's own test grid, so it discriminates nothing there. Of the 8 defects no reference-free check caught, six are the wrong-coefficient and over-smoothed predictions of the three equations the checker cannot express, and two are the identically zero field on a problem whose boundary data is zero, which no check without a reference can distinguish from a solution. We report these limits explicitly rather than as a footnote, because a verification layer inherits the expressiveness of its equation set.

We make no claim of statistical significance: with 3 to 5 seeds the exact sign test cannot reach p<0.05, so differences are reported with their spread. Everything here runs on a CPU; no GPU or multi-GPU path was exercised, and the cost figures are single-threaded CPU measurements.
```

Note the substitutions made above for plain text: `64x64` for `64\times64`, `L2` for `L^2`,
`1.4-1.9x` for `1.4--1.9\times`, `Allen-Cahn` for `Allen--Cahn`, `p<0.05` written out. Keep them.
The block above is the manuscript's abstract verbatim, and a test fails if the two drift apart
(`scripts/test_tables_in_sync.py`).

## Categories

Checked against `https://arxiv.org/category_taxonomy` when this file was written. The current
description of `cs.LG` is *"papers on all aspects of machine learning research ... including also
robustness, explanation, fairness, and methodology. cs.LG is also an appropriate primary category for
applications of machine learning methods"*, which covers an evaluation-methodology contribution.
`physics.comp-ph` is *"all aspects of computational science applied to physics"*, which covers the
Burgers/Poisson/Helmholtz/Allen--Cahn half. Category names and descriptions change; re-read that page
before submitting.

`cs.MS` (Mathematical Software) is the alternative primary if the paper is read as a software paper
rather than as an evaluation. It is **not** the recommendation here, because the contribution is the
measurement, not the library.

## Source package

`make bundle` produces `arxiv/pinneapple-preprint.tar.gz` from the sources only:

- `paper.tex`, `refs.bib`, `paper.bbl`, `Makefile`, `REPRODUCE.md`, `README.md`
- `tables/` (12 `.tex` fragments), `figures/` (6 PDFs)
- `scripts/`, `experiments/` (the corpus code, for a reader who wants to re-run it)

The compiled `paper.pdf` is **not** in the bundle; arXiv compiles from source. Excluded:
`_work/` (per-case scratch directories) and `__pycache__`.

Two points checked against `https://info.arxiv.org/help/submit_tex.html` and
`https://info.arxiv.org/help/sizes.html`:

- The preamble loads only packages that work with `pdflatex` (no `fontspec`, no engine-specific
  options) and every source file is pure ASCII, so arXiv's default processor should handle it. This
  is a static check, not a build: no `pdflatex` is installed here, and the local build uses
  `tectonic` (XeTeX) to avoid requiring a TeX distribution. The first real test of arXiv's processor
  is the compiled preview, which is why inspecting it is on the checklist below.
- The figures are **vector PDF**, which those pages name as the preferred format for diagrams, and
  so no raster image approaches the 34-megapixel warning threshold introduced in 2026. The bundle is
  about 124 KB, orders of magnitude below any size at which arXiv warns or rejects.
- `paper.bbl` is included because the TeX help page asks for `.bib` or `.bbl` when BibTeX is used.
